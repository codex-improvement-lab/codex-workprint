# Codex Workprint 0.3.0-rc.2 release candidate

## Every agent run leaves a Workprint.

Turn a Codex JSONL run into a privacy-safe, verifiable visual receipt. **No prompts. No code. No uploads.**

```bash
codex exec --json "<your task>" | codex-workprint build - --title "<public title>" --out ./workprint --open
```

The new Run Receipt first screen answers four bounded questions: what run this is, what was publicly observed, what relation matters most, and what stayed private. Its story is selected from fixed templates over the existing default-deny Run IR; it is not model-generated and does not infer recovery, correctness, authenticity, causality, or impact.

The seven-file bundle remains the same contract: deterministic HTML, README SVG, 1200×630 share card, public IR, privacy receipt, embed, and SHA-256 manifest. `verify` still rejects byte drift. The full Run Sheet, ordered observations, item pairing, turning points, mobile route, and historical demos remain available below the receipt.

## First-run and sharing improvements

- `build -` reads bounded JSONL from stdin.
- `--open` opens the generated local HTML after a successful build.
- `--project`, `--by`, `--release`, `--public-url`, and `--lang` are explicit public opt-ins. They are never inferred and cannot change shape identity; public URLs containing credentials, query strings, or fragments are rejected.
- Share falls back to local caption copy unless an explicit credential-free HTTPS public URL exists; the page performs no upload or fetch.
- Download card, Copy verify command, Copy caption, Replay story, and paper/carbon controls are visible on the first screen.
- The visual Privacy Receipt lists both the public whitelist and eight excluded private categories.

Unsupported Node versions now fail in a plain-JavaScript bootstrap before TypeScript loads. A `.js` preflight test prevents Node 22.16-style false-green test discovery. The supported baseline remains Node.js 22.18.0 or newer with zero runtime dependencies.

## Publication-blocker repairs

- The share-card headline now renders `→` through the fixed Unicode path. All visible public share-card text is coverage-checked, and any missing glyph rejects the build instead of becoming `?`.
- “Build yours” never reuses the artifact title. It exposes inert `<your task>` and `<public title>` placeholders and is covered against shell substitution, quotes, separators, pipes, backslashes, and PowerShell interpolation.
- The 4931-byte Run IR 0.1 schema is restored to SHA-256 `fceb9134…0299`. Explicit identity now belongs to the distinct Run IR 0.2 schema; the current verifier explicitly rejects legacy IR 0.1.
- `open items` and status-absent observations are separate counters. The Verify action is accurately named, clipboard fallback is visible and selected, native-share text no longer duplicates its URL, and the standard caption is shorter.

## Deterministic Unicode share cards

Run share cards use a fixed GNU Unifont 17.0.05 Plane 0 bitmap source and indexed-color encoding. The checked-in Chinese example, `修复登录失败并验证发布`, has 11/11 title-glyph coverage and compiles without question-mark replacement. UI localization, BiDi/complex-script shaping, supplementary-plane coverage, and emoji coverage are not claimed.

The repository social preview is byte-identical to the primary Run share card: 1200×630, indexed PNG, 756798 bytes, and strictly below 1,000,000 bytes.

## Three questions. One Workprint.

Unified Profiles remain the distinct second product layer:

- Continuity asks “What still holds after handoff?” and renders a seam / black-box form.
- Goal Delta asks “What evidence stops carrying when the goal changes?” and renders a fault / shockwave form.
- Context Receipt asks “What context was prepared, observed, or absent?” and renders a slice / x-ray form.

`profile inspect/build/verify`, `workprint-profile/0.1`, `workprint-profile-ir/0.1`, profile-specific verdict sets, source-reference validation, and separate seven-file bundles are preserved. The wrong verifier still rejects the other bundle type.
